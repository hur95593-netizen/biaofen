> 本目录是飙分项目的维护者文档,面向后续接手的开发者(按新手也能读懂的标准编写)。
> 三端详细设计:[Web 端](web.md) · [iOS 端](ios.md) · [服务端](server.md)
> 线上版本同步维护在 Confluence:`~xiang.hu@shopee.com` 空间下的 biaofen/web/ios/server 四页。

## 1. 项目是什么

飙分是一款由「二七王」改编的升级/拖拉机类扑克游戏,支持:

- **单机对战**:1 个真人 + 2~3 个电脑 AI(Web 网页版、iOS 原生 App 各一套)
- **联机对战**:房间码开房,3/4 人同桌,空位由 AI 补位,掉线 AI 托管(Web 与 iOS 客户端可同桌互通)

完整游戏规则见仓库根目录的 [飙分-规则.md](../飙分-规则.md)(规则的唯一权威来源,改规则先改它)。

## 2. 游戏规则速览

| 项目 | 规则 |
|------|------|
| 牌 | 2 副共 108 张(含 4 张王)。3 人局每人 33 张、底牌 9 张;4 人局每人 25 张、底牌 8 张 |
| 常主 | 大王、小王、所有 3、所有 2 永远是主牌(注意:7 是普通牌,这是与二七王的核心差异) |
| 主牌大小 | 大王 > 小王 > 主3 > 副3 > 主2 > 副2 > 主A > 主K > … > 主4 |
| 牌型 | 单张 / 对子(同花色同点数两张)/ 拖拉机(同花色连续对子,主 A 两头都连但不桥接)/ 甩牌(首攻多张"必大"主牌) |
| 跟牌 | 按 拖拉机→对子→单牌 优先级凑同结构,必须先出满该组的牌;被迫拆单张主牌凑数时必须出最大的(**跟大**),副牌不跟大 |
| 分数牌 | 5=5 分、10=10 分、K=10 分,全场共 200 分;只有闲家捡分 |
| 喊分 | 每局重新喊,100 起、200 封顶、10 的倍数,只要高于当前最高可任意跳喊;最高者坐庄;闲家线 L = 200 − 喊分 |
| 翻底 | 最后一墩闲家用主牌赢则翻底牌捡分:单牌/甩牌 ×1,对子/拖拉机 ×2 |
| 结算 | 底分 =(喊分−90)×10;闲家 0 分庄家光头(−2 底/闲家),闲家 < L 庄赢(−1 底),= L 平,> L 闲家赢,每多 30 分升一档(+1 底/档,上不封顶) |

## 3. 三端架构总览

项目的核心设计决策:**一份规则,三份对齐实现**。规则引擎(牌、牌型、跟牌、状态机、AI)在三种语言里各有一份 1:1 移植,行为完全一致:

| 端 | 语言/框架 | 角色 | 引擎位置 |
|----|-----------|------|----------|
| Web | 原生 JavaScript(零框架零依赖) | 单机版(逻辑全在浏览器)+ 联机瘦客户端 | `src/*.js` |
| iOS | SwiftUI,iOS 17+ | 单机版(逻辑全在 App)+ 联机瘦客户端 | `ios/BiaofenCore/`(独立 Swift Package) |
| 服务器 | Go + gorilla/websocket | 联机权威服务器:牌局状态只存在服务器,客户端只收"按座位打码"的视图 | `server/game/`(**移植蓝本,改动的第一现场**) |

> **维护铁律:改引擎逻辑必须三端同步。**惯例顺序:先改 Go(`server/game/`,它有最全的测试和 AI 对战台),跑通测试后按同样的函数结构移植到 Swift(`ios/BiaofenCore/`)和 JS(`src/`)。三端的文件、函数名刻意保持一一对应,diff 对照很直观。

联机时序(单机则把"服务器"换成本地引擎):

```text
客户端(Web/iOS)                Go 服务器
    |  --- WebSocket /ws --->      |
    |  create/join(房间码)         |  Hub 找房间,一房一 goroutine
    |  <--- joined(seat+token) --- |
    |  start/bid/trump/bury/play   |  房间校验合法性 -> 更新 Game 状态
    |  <--- state(按座位打码) ---- |  每个座位只看到自己的手牌
    |  <--- event(轻量事件) ------ |  喊分/收墩等 toast 提示
```

## 5. 三端共通的核心概念(先读这节再看代码)

### 5.1 Card(牌)

一张牌 = `{suit, rank, copy, id}`。suit 取 `S/H/D/C/JOKER`;rank 2~14(11=J,12=Q,13=K,14=A),王为 16(小)/17(大);copy 0/1 区分两副牌里的同名牌;id 格式 `"S-5-0"`(花色-点数-副数),**三端与协议里的 id 完全一致**,联机时客户端只传牌的 id 列表。

### 5.2 两套独立刻度(最容易踩的坑)

- **Strength(比大小)**:决定谁压谁。主牌区间 184~200(大王 200、小王 199、主3 198、副3 197、主2 196、副2 195、主A 194…主4 184),副牌就是 4~14。
- **TractorRank(拖拉机相邻)**:决定连不连,与大小无关。每张牌有 `lane`(赛道:王自成孤岛、主花色一条、各副花色各一条)和 `pos`(自然位置);主 A 特殊,pos=1 兼 alt=14(既接 2 也接 K,但不能桥接两头)。

例:红桃主时,单张比大小 主3 压 主K;但拖拉机相邻里 3 回到 2 和 4 中间,所以 3344、A22 都是拖拉机。两套刻度分别由 `strength()` 和 `tractorRank()` 实现,绝不要混用。

### 5.3 Combo(牌型)与收墩

`detectCombo(cards, trump)` 识别一手牌:single / pair / tractor,非法组合返回空。`beats(b, a)` 判断压制(同型同长才可比;主杀副;同花色比 top)。甩牌(throw)不经 detectCombo,由状态机单独校验(见 5.5)。收墩 = 遍历一圈出牌找最大。

### 5.4 跟牌合法性 isLegalFollow

核心约束:必须出满首攻组的牌;组内有取舍时按结构跟(有对必须跟对、有等长拖拉机必须跟拖拉机);**主牌被迫拆单凑数时必须出手里最大的单张("跟大")**——这条规则是 AI 拉主策略的支点。

### 5.5 甩牌(throw)

首攻允许出多张不成型的主牌,校验条件:**未见的主牌里没有任何一张能大过甩出的最小者**(必赢才准甩;底牌里的主也按未见算,宁可保守)。甩牌墩必归首家;跟牌方出满同数量该组牌即可,无结构要求;翻底倍数按 ×1 计。

### 5.6 联机的"按座位打码"视图

服务器每次状态变化后,给每个座位单独生成视图:手牌只发本人,他人只给张数;底牌只在扣底阶段发给庄家(标记用)、结算后才全量翻开。**防作弊的关键就在这里**——客户端从协议上就拿不到别人的手牌。

## 6. 测试体系

| 命令 | 覆盖 |
|------|------|
| `npm test` | JS 引擎规则用例(53 项:牌型识别、跟牌合法性、边界) |
| `node test/sim.js` | JS 全 AI 自动对局 200 局:每手校验合法性、结算守恒 |
| `go test ./...` | Go 全量:规则用例 + 3/4 人各 300 局模拟 + 服务器协议测试 |
| `go test ./server/game/ -run TestAB3P -v` | AI 策略 A/B 对战台:新旧策略按角色互打 2000 局 ×4 组,量化胜率(**改 AI 必跑**) |
| `cd ios/BiaofenCore && swift test` | Swift 全量(与 Go 同套用例 + 模拟),在 macOS 直接跑、不需要模拟器 |

三个模拟器都断言:AI 永不打出非法牌、每局结算 delta 总和为 0、闲家分不为负。改完任何引擎逻辑,三端测试全绿才算完成。

## 7. 构建与部署

```bash
# 本地起联机服务器(同时托管 Web 前端)
go run ./server -root .          # http://localhost:8124/online.html,局域网 IP 会打印在日志里

# 打包 Web 单文件版(改过 src/ 或 css/ 后必跑)
node build.js                    # 产出 飙分-电脑版.html / 飙分-手机版.html

# 部署:Render 一键(读 render.yaml),或
go build -o biaofen ./server     # 单二进制(前端已 go:embed 内嵌),扔到任何服务器直接跑
```

## 8. 新维护者快速上手清单

1. 读 [飙分-规则.md](../飙分-规则.md),亲手玩几局(Web 开 index.html 最快)。
2. 读本页第 5 节的共通概念,然后从 `server/game/cards.go` 开始顺序读 Go 引擎(五个文件共约 1500 行,注释密集)。
3. 跑一遍第 6 节的全部测试,确认环境正常。
4. 改规则:先改规则文档,再按 Go → Swift → JS 顺序同步,三端测试全绿。
5. 改 AI:在 Go 里做,用 `TestAB3P` 的 A/B 对战台验证胜率不回退(有过"直觉正确但数据打脸"的先例,见 [server.md](server.md) AI 章节),再同步另外两端。
6. 三端各自的界面/网络细节,读对应子文档:[web.md](web.md) · [ios.md](ios.md) · [server.md](server.md)。
